> 这是第 EP04 篇，产品是 **种子 OS**。

很多人抱怨 Agent 的记忆力和对话胡扯。

每次打开新对话，都要交代大量的事情。一遍又一遍地开始新的对话，反复提供同样的上下文。他们以为 Notion 有核心记忆功能，以为 Claude Code 记得一切。他们以为 AI 是机器，拥有无穷无尽的计算能力。

但他们没意识到一件事：

AI 的大脑不是计算机。它是 LLM 推理大模型。它的记忆，可以理解为「七秒的金鱼记忆」。它只是在通过搜索、检索和推理来给出答案。如果数据没有来源，来源不真，或者记忆存储不够，它就会开始胡编乱造。

所以我花了一个月，从空文件夹开始，搭了一套操作系统。不是为换更好的 AI 工具——我自己用 Claude Code + Obsidian + Hermes，朋友用 Obsidian + Hermes 也够用。是为了解决一个根本问题：怎么做好个人数据管理，让有价值的个人数据留存下来，让 AI 真正「记得、理解」我。这篇文章是系列开篇，先把整体架构讲清楚。

---

这还只是「重复交代」的表层问题。更深层的问题是：上下文不是让 AI 全部读完，是让它能**检索到**该读什么。

这也是 RAG（检索增强生成）的工作方式。AI 不需要记住你的一切，它需要的是——当你问一个问题时，能从你的数据里快速找到相关的部分，然后基于这些部分来推理和回答。

我做这件事的初衷，产生于一个很朴素的想法。当时我正在用一套由 Input、Process、Output 目录组成的线来管理工作，加上 Skill 调用和 Knowledge 体系。我突然意识到：我们其实很渴望像使用 Notion 那样去管理人生。Notion 提供了很多好看的模板，我们希望通过这些模板搭建的系统来管理一切。但 Notion 最大的问题是——所有数据都要你每天手动输入，模板才能被调动。你不更新，它就是个空架子。

我想：如果 AI 能把「数据输入」这件事给做了呢？就像打扫房间一样，房间越井井有条，工作效率就越高。如果数据能自动流入、自动归类，那么这套管理体系就能真正帮我管理人生，而不是给我增加负担。

所以从「与 AI 协同」，我转变了一个思路：**基于数据管理，搭建一个 AI 管理 OS**。

之所以叫「种子 OS」，是因为底层逻辑是一致的——数据分层、流程化、标准化。但每个人种下去之后，长出来的东西不一样。有人关注健康，有人关注财务，有人关注教育成长，有人关注商业或个人 IP。种子是一样的，土壤和照料方式不同，结出的果实就不同。

[配图：AI运行逻辑流程图（RAG检索→回流判断→ReAct）]

---

那怎么解决？答案不在 AI，也不在 Obsidian，而在数据管理。

所有你看到的显性呈现——Dashboard、管线、输出物——说到底都是管理后的结果。先让数据分层、结构化、可调用，再让 AI 按需读取，而不是全塞给它。

打个比方。想象你有一个一直跟着你的助手，无论你见谁，他都了解你的背景、上次聊到哪、你的偏好是什么。这很好。但哪怕最聪明的助手，也记不完七十二万字。所以他需要一套档案系统——不是全背下来，是知道什么信息在哪，随时能调。

这就是整套系统真正起作用的地方。

如果你还没用过 Obsidian，简单介绍一下：它是一款本地优先的笔记软件。你的笔记不是存在某个公司的服务器上，是以 Markdown 文件的形式，存在你自己的电脑里。

这意味着三件事。

数据主权在你手里。笔记存在本地，没有「平台倒闭数据没了」或「会员到期看不了笔记」的尴尬。你的笔记永远是你的。

Markdown 是通用格式。任何文本编辑器都能打开，任何 AI 都能直接读取，不像某些笔记软件的私有格式，换工具就要导出导入。

双向链接。你可以在笔记 A 里引用笔记 B，笔记 B 会自动知道自己被谁引用了。所有笔记连起来，就形成了一张知识图谱。

[配图：Obsidian 界面示意图——左侧文件树 + 中间编辑区 + 右侧图谱]

我选择 Obsidian，原因很直接。

它输出的 Markdown 文件，是 AI 阅读最舒服的格式。纯文本、标准化、无冗余。

它本身是人类笔记软件，人理解起来也很舒服。写笔记、看笔记、整理笔记，体验都很好。

最关键的：它是目前最适合人与 AI 共读的上下文工具。文件在本地，AI 可以直接读取；格式是 Markdown，不绑定任何平台；全部本地化，无论我今天换掉哪个 AI 工具，这些东西会一直存在这里。

这套系统最终呈现为三个层面。

[配图：种子 OS 三层面总览图——目录层面 / 工作流层面 / Dashboard 层面]

目录层面：数据如何分类归档，LLM 如何检索调用。

工作流层面：数据从 Input 到 Output 的完整流转路径。

Dashboard 层面：每天打开看到的驾驶舱，所有状态一目了然。

这三个层面背后，是七层架构在支撑。今天不展开，后续每一篇讲一层。

---

从 5 月 23 日写下第一版规则到现在，短短半个多月，这套系统迭代了 23 个版本。129 次对话、94 条判断、72 万字的 Knowledge 沉淀——这些数字不是炫耀，是证明一件事：当数据管理做对了，AI 的迭代速度是指数级的。

如果你想动手搭建，前置条件很简单：

1. **Obsidian**（笔记底座）
2. **Hermes**（AI 入口，基于 GitHub 开源项目部署）
3. **Obsidian Terminal 插件**（终端集成，支持 Termux 环境）

相关链接：
- Obsidian：https://obsidian.md/
- Hermes：https://github.com/NousResearch/hermes-agent
- Obsidian Terminal：https://github.com/polyipseity/obsidian-terminal

[配图：Obsidian Terminal 插件示意图——左侧文件树 + 右侧终端面板]

装好这三个，做好布局，基本面就能跑通。给 Hermes 装上对应的能力，数据流就能转起来。
