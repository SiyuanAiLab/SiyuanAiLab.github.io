# Browser QA Runbook

> 一句话定义：把网页验收变成 Agent 可以逐步执行、截图留痕、失败回报的检查流程。

## 这个能力解决什么问题

网页流程经常不是“页面能打开”就算完成，还要确认按钮、表单、跳转、移动端布局和关键文案都正常。Browser QA Runbook 的价值，是把这些检查点固定下来。

## 核心逻辑

输入是目标页面、用户路径和验收标准。处理过程是逐步打开页面、执行动作、截图、记录异常。输出是一份可复查的页面验收记录。

## 技术结构

它通常由浏览器自动化工具、截图工具、断言规则和人工复核清单组成。Agent 负责执行重复检查，人负责判断视觉和业务语义。

## 为什么值得参考

它把“我看一下页面”变成了可复用的验收流程，适合用在静态站、活动页、表单页和内容发布前检查。

## 为什么不建议直接套用

不同网站的关键路径不同。直接套用别人的检查点，容易漏掉自己的转化按钮、栏目入口或移动端断点。

## 如何改造成自己的版本

- 先列出一个页面的关键用户路径。
- 给每一步写清楚期望结果。
- 固定截图尺寸，例如 375px、768px、1440px。
- 把异常输出格式固定成“位置、现象、影响、建议”。

## 适用场景

适合网页改版验收、内容页上线检查、表单流程验证和响应式截图复核。

## 不适用场景

不适合绕过登录、抓取私域内容或替代人工审美判断。
