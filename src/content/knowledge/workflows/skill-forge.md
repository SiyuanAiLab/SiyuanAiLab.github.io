# Skill Forge

> 一句话定义：把一个场景想法加工成一套能交付、能复用、能被别人看懂的 Skill 结构。

## 这个 Skill 解决什么问题

很多工作流已经讲得清楚，但还不能变成 Skill。原因通常不是模型不会做，而是触发条件、输入材料、输出格式和边界都没有写清楚。

## 核心逻辑

它接收一份场景说明，输出 Skill 名称、适用场景、目录结构、主要文件、执行步骤、失败条件和验收标准。

## 为什么值得参考

它强调交付结构。对非技术人来说，这相当于把“我会做”变成“别人也能照着跑”。

## 为什么不建议直接套用

Skill 不是越大越好。直接套用模板容易把多个任务塞进一个 Skill，导致触发范围太宽，实际使用时不稳定。

## 如何改造成自己的版本

- 给 Skill 写一个明确的触发句。
- 把输入材料分成必需和可选。
- 把输出物控制在一种主格式里。
- 写 3 个成功样例和 2 个失败样例。

## 适用场景

适合把咨询 SOP、内容生产流程、资料处理流程做成可复用能力包。

## 不适用场景

不适合还没有稳定流程、每次都要临场判断的任务。
