# MCP Tool Router

> 一句话定义：给 Agent 的工具箱加一层调度规则，让它知道什么时候该用哪个工具、什么时候不能用。

## 这个能力解决什么问题

当 Agent 同时能访问文件、网页、数据库和协作工具时，风险不在于工具少，而在于调用边界不清。MCP Tool Router 的价值，是把工具选择变成可管理的流程。

## 核心逻辑

输入是任务意图和可用工具清单。处理过程是判断任务类型、权限要求、输入材料和风险级别。输出是推荐调用链路或拒绝调用原因。

## 技术结构

核心结构包括工具注册表、权限标签、路由规则、调用日志和失败回退策略。它不替代工具本身，而是管理工具之间的选择和边界。

## 为什么值得参考

它能降低 Agent 乱调工具的概率，也方便团队复盘：到底是哪一步、哪个工具、哪个权限边界出了问题。

## 为什么不建议直接套用

工具权限和业务风险强相关。别人的路由规则不能直接搬到自己的工作环境，尤其不能绕过密钥、客户数据和发布权限。

## 如何改造成自己的版本

- 给每个工具写一句“只能用来做什么”。
- 把高风险动作单独列成必须人工确认。
- 记录每次工具调用的输入、输出和失败原因。
- 先从 3-5 个常用工具做小范围试运行。

## 适用场景

适合多工具 Agent、MCP server 编排、内部知识库查询和协作工具连接。

## 不适用场景

不适合用来处理未经授权的数据、跳过权限边界，或替代生产内容上线前的人工确认。
